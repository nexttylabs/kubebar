# fix: Restore v0.2.3 release notes

## Summary

- Summary: The v0.2.3 release workflow can extract finalized release notes.

Add the missing finalized `0.2.3` changelog section so the release workflow
that already built `Kubebar.zip` can pass its `Extract Release Notes` step when
the tag is replayed.

## Task

- Type: fix
- Scope: release changelog
- Owner: imm-work
- Verification: automated

## Origin

GitHub Actions run 25850620748 failed in the `Release` workflow on tag
`v0.2.3`. Public job metadata shows the `Extract Release Notes` step failed.
Local reproduction with `./scripts/extract-release-notes.sh 0.2.3` reports:
`ERROR: Expected exactly one finalized changelog section for 0.2.3, found 0`.

## Research

- `.github/workflows/release.yml` extracts notes with
  `./scripts/extract-release-notes.sh "$VERSION"` before creating the GitHub
  Release.
- `scripts/extract-release-notes.sh` requires exactly one finalized heading in
  the form `## [0.2.3] - YYYY-MM-DD` and at least one bullet entry.
- `CHANGELOG.md` currently has only `[Unreleased]`, `0.2.2`, `0.2.1`, and
  `0.1.0` sections.
- `v0.2.3` includes user-visible Pod resource usage visualization, readability
  improvements, and README/release documentation updates.

## Decisions

- Add a manually curated `0.2.3` section because no `changelog.d` fragments are
  present for this already-tagged release.
- Keep `[Unreleased]` empty after moving the already-released notes into
  `0.2.3`.
- Prepare tag replay guidance but do not move local or remote tags without a
  separate explicit action.

## Assumptions

- The intended release date for `0.2.3` is 2026-05-14, matching the failed
  workflow run and tag date.
- The local `main` branch is the target branch for the changelog hotfix.

## Scope Boundaries

- In scope: `CHANGELOG.md`, this spec, this plan, and local verification.
- Out of scope: app code, build scripts, workflow permissions, publishing a
  GitHub Release, and moving remote tags.
