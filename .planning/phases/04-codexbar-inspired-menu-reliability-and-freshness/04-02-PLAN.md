<threat_model>
Trust boundary: saved app config controls which context and watch targets the
app reads through `kubectl`.

Threats:
- T-01 wrong context: changing setup context must clear loaded targets and load
  targets for the new context only.
  Mitigation: model and tests expose the target context to load.
- T-02 lost watchlist: a target-load failure while editing must not erase the
  selected watchlist.
  Mitigation: tests assert selection is preserved after failure.
- T-03 hidden setup loop: first launch with partial config must visibly stay in
  setup while loading the missing target choices.
  Mitigation: model exposes visible surface and needed loads.
</threat_model>

  <action>
Create `MenuRuntimeState` under `KubebarCore/Models`.

Model responsibilities:
- Represent whether the visible surface is setup or the normal menu.
- Initialize from `AppConfig`.
- Expose whether contexts should load when setup is shown.
- Expose the selected context whose watch targets should load.
- Handle opening setup from a configured app.
- Handle selecting a setup context by clearing available targets and moving
  target loading to the correct context.
- Handle successful and failed target loading.
- Produce the next `AppConfig` when setup can be completed.

Suggested names:
- `public enum MenuSurface: Equatable, Sendable { case setup, menu }`
- `public struct MenuRuntimeState: Equatable, Sendable`

Keep async catalog calls out of this model.
