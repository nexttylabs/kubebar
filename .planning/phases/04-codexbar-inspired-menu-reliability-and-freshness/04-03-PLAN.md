<threat_model>
Trust boundary: background refresh reads cluster state on a timer through local
`kubectl`.

Threats:
- T-01 noisy polling: too-frequent refresh can overload a local kubeconfig or
  weak cluster connection.
  Mitigation: use a fixed list of conservative cadence options and persist only
  valid intervals.
- T-02 stale confusion: failed refresh must not appear current.
  Mitigation: keep existing stale-first failure semantics and show last updated
  information.
- T-03 duplicate timers: repeated setup completion or view model refresh can
  start multiple loops.
  Mitigation: keep one cancellable refresh task and restart it only when cadence
  changes.
</threat_model>
