real launch smoke test. Kubebar has already had failures where tests passed but
the visible menu was missing or collapsed.

<threat_model>
Trust boundary: the script controls a local GUI process.

Threats:
- T-01 process damage: broad kill commands could stop unrelated apps.
  Mitigation: match the exact `Kubebar` process name and/or bundle id only.
- T-02 stale binary: launching an older app hides build failures.
  Mitigation: launch `DerivedData/Build/Products/<configuration>/Kubebar.app`
  from the same derived data path used by the quality gate.
- T-03 false success: `open` can return before the app is actually running.
  Mitigation: poll for the process and print the PID before success.
</threat_model>

<task type="auto">
  <name>Task 1: Add local compile-and-run script</name>
  <files>scripts/compile-and-run.sh</files>
  <read_first>scripts/swift-quality-gate.sh, project.yml</read_first>
  <action>
Create `scripts/compile-and-run.sh` as a bash script with `set -euo pipefail`.

Behavior:
- Resolve repo root from the script location.
- Use `XCODE_CONFIGURATION:-Debug` and `XCODE_DERIVED_DATA_PATH:-DerivedData`.
- Run `./scripts/swift-quality-gate.sh local`.
- Resolve the app path as `DerivedData/Build/Products/<configuration>/Kubebar.app`.
- Fail with a clear message if the app bundle does not exist.
- Quit any already-running Kubebar instance using exact bundle id
  `com.nextty.kubebar` when possible, with exact process-name fallback only.
- Launch the built app with `open -n`.
- Poll for a running `Kubebar` process for a bounded timeout.
- Print the launched PID and app path on success.
  </action>
  <verify>bash -n scripts/compile-and-run.sh</verify>
  <acceptance_criteria>

    - `scripts/compile-and-run.sh` contains a bounded polling loop for the PID

  </acceptance_criteria>
