<threat_model>
Trust boundary: Kubebar converts local `kubectl` reads into a menu bar health
signal that operators may trust before opening deeper tools.

Threats:
- T-01 stale trust failure: an old successful snapshot can remain `OK`,
  `Watch`, or `Bad` after it is no longer current.
  Mitigation: mark snapshots older than `2 * refreshIntervalSeconds` as
  `Stale` and show the last successful update age.
- T-02 failure noise: repeated failed polls can make the menu distracting.
  Mitigation: keep the same stale presentation and update only the stale reason
  and last successful update age.
- T-03 unsafe error detail: raw command output can expose local paths or token
  wording.
  Mitigation: keep short display-safe reasons and preserve existing redaction
  behavior.
- T-04 refresh race: overlapping manual and automatic refreshes can start too
  many `kubectl` commands or let an older result overwrite newer state.
  Mitigation: keep a single in-flight refresh and disable `Retry now` while it
  is running.
</threat_model>

  <action>
Prevent overlapping refreshes from manual retry and the automatic loop.

Concrete target state:
- Add a small testable core type `RefreshGate` that tracks whether refresh work
  may start.
- `RefreshGate.begin()` returns `true` for the first refresh and `false` while a
  refresh is already in progress.
- `RefreshGate.finish()` clears the in-flight state.
- Add `RefreshGateTests` proving two immediate `begin()` calls allow only one
  refresh and that `finish()` allows the next refresh.
- Use `RefreshGate` or an equivalent in-flight guard from `MenuBarViewModel`.
- If `refreshNow()` is called while a refresh is running, it returns without
  starting a second detached refresh.
- Automatic refresh uses the same guarded path as `Retry now`.
- Add a published boolean named `isRefreshing` and pass it into
  `MenuBarRootView`.
- In `MenuBarRootView`, the `Retry now` button is disabled while refresh work is
  running.
- When the refresh finishes, the button becomes enabled again.
- `Retry now` remains enabled when idle in both healthy and stale displays.
- Do not add a persistent progress panel or next-refresh countdown.
  </action>
