<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fixture catalog -> app display | Test/QA data becomes the app-visible display model. |
| fixture metadata -> committed evidence | QA strings may later be copied into UAT and docs. |
| kubectl failure fixture -> stale display | Failure evidence must not expose raw command output or credentials. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | `MenuStateFixtureCatalog` | mitigate | Fixtures use fixed `ClusterSnapshot`, `SetupFlowState`, and `HealthEvaluator`; no fixture shells out, writes config, or mutates a real cluster. |
| T-07-02 | Information Disclosure | kubectl failure fixture metadata | mitigate | Tests deny raw stderr, token-like text, kubeconfig paths, full JSON, and command transcripts; failure display uses safe stale wording. |
| T-07-03 | Elevation of Privilege | QA mode surface | mitigate | This plan creates data only; later app launch mode must remain Debug-only and outside production menu controls. |
| T-07-04 | Tampering | generated evidence | mitigate | Fixture metadata is deterministic; later generation must write temp output and not overwrite human UAT evidence. |
| T-07-05 | Information Disclosure | UAT/docs/screenshots | mitigate | Metadata fields use app-owned strings and sanitized evidence paths under `docs/assets/qa/`. |
</threat_model>
