<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| launch args/environment -> QA fixture | Untrusted local launch input selects a fixture. |
| QA fixture -> MenuBarExtra UI | Debug-only data is rendered by the real app shell. |
| smoke script -> local app launch | Script starts the built app and records process evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | QA launch mode | mitigate | QA mode reads fixture data only; it must not call kubectl, write config, or mutate a cluster. |
| T-07-02 | Information Disclosure | visible kubectl failure fixture | mitigate | Fixture display is pre-sanitized; script records app path/PID/state only, not raw stderr or kubeconfig data. |
| T-07-03 | Elevation of Privilege | `KubebarApp` QA selector | mitigate | Gate all QA launch code behind `#if DEBUG`; state selection happens through launch args/environment only, with no production menu control. |
| T-07-04 | Tampering | smoke evidence | mitigate | Script appends no UAT data and overwrites no human evidence; it prints process evidence for manual recording. |
| T-07-05 | Information Disclosure | process evidence | mitigate | Evidence output is limited to app path, PID, running status, and fixture state ID; no command transcripts or cluster details. |
</threat_model>
