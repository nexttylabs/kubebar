## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| kubectl -> KubebarCore | External command stdout/stderr and JSON enter app-owned models. |
| Kubernetes API data -> display contracts | Untrusted cluster metadata is condensed into short menu-safe fields. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01-01 | Information Disclosure | KubectlClusterReader.runKubectl | mitigate | Never store raw stdout in display models; sanitize stderr by using the first non-empty line, replacing `NSHomeDirectory()` with `~`, returning `kubectl failed` for token/password/certificate-looking text, and capping the reason at 96 characters. Verify with a stderr fixture containing `/Users/example/.kube/config` and `token`. |
| T-05-01-02 | Tampering | JSON decoding in KubectlClusterReader | mitigate | Decode with typed Decodable records. Malformed node/pod/event/workload JSON becomes `SnapshotSection.unavailable(reason:)`; no malformed section can contribute healthy counts. Verify malformed event JSON leaves nodes and pods available while warning events are unavailable. |
| T-05-01-03 | Information Disclosure | KubectlRead and workload metadata reads | mitigate | Read only nodes, pods, warning events, and supported workload metadata for Deployment, StatefulSet, DaemonSet, and CronJob. Do not add any `secrets` command. Verify command arrays in tests do not include `secrets` or raw shell strings. |
| T-05-01-04 | Elevation of Privilege | Command execution boundary | mitigate | Keep `CommandRunning` and argument arrays with `["--context", contextName]`; do not add shell interpolation or direct `Process` calls in the reader. Verify FakeMultiCommandRunner sees exact argument arrays. |

Refactor `KubectlClusterReader` so each kubectl section is decoded independently and warning events become `WarningEventRecord` values.

Decision trace:
- Preserve reason, namespace, involved object, timestamp, message, and count fields so Plan 02 can render `Reason + namespace/object + age` per D-02.
- Preserve occurrence count and newest observed time so Plan 02 can group duplicates by `reason + involved object` per D-03.
- Store only normalized fields and short-safe failure reasons, not raw/full kubectl event output, per D-04 and D-05.
- Treat successful empty JSON lists as valid empty states per D-14.
- Treat malformed JSON as a section failure per D-15.

Keep these command shapes:
- Nodes: `["--context", contextName, "get", "nodes", "-o", "json"]`
- Pods: `["--context", contextName, "get", "pods", "--all-namespaces", "-o", "json"]`
- Warning events: `["--context", contextName, "get", "events", "--all-namespaces", "--field-selector", "type=Warning", "-o", "json"]`

Implementation details:
- Change raw read handling so a failed command or malformed JSON for one section produces `SnapshotSection.unavailable(reason:)` for that section instead of throwing the whole snapshot away.
- Keep a whole-refresh throw only when no section can be read at all. The thrown reason must be sanitized.
- Rename `decodeEventCount(_:)` to a richer decoder such as `decodeWarningEvents(_:) -> [WarningEventRecord]`.
- Decode the legacy core Event shape with `metadata.namespace`, `reason`, `message`, `involvedObject.kind`, `involvedObject.namespace`, `involvedObject.name`, `lastTimestamp`, `eventTime`, and `count`.
- Decode the events.k8s.io Event shape with `note`, `regarding.kind`, `regarding.namespace`, `regarding.name`, `eventTime`, `series.lastObservedTime`, `series.count`, `deprecatedCount`, and `deprecatedLastTimestamp`.
- Prefer observed time in this order: `series.lastObservedTime`, `deprecatedLastTimestamp`, `lastTimestamp`, `eventTime`, then metadata creation time when present.
- Use `ISO8601DateFormatter` to parse timestamps and keep `observedAt` nil if parsing fails.
- Normalize missing reason to `Unknown`, missing count to `1`, and use `message ?? note` shortened later by HealthEvaluator.
- Empty JSON lists are valid: `.available([])` for events, `.available(NodeSummary(ready: 0, total: 0))` for nodes, `.available(PodSummary(running: 0, total: 0))` for pods.
- Add `private func displaySafeFailureReason(_ raw: String) -> String`: trim whitespace, use the first non-empty line, replace `NSHomeDirectory()` with `~`, return `kubectl failed` if the line contains case-insensitive `token`, `password`, `client-key-data`, `client-certificate-data`, or `certificate-authority-data`, and cap output at 96 characters.
- Do not store raw kubectl JSON, raw stdout, or full stderr in `ClusterSnapshot`.

Replace the current `phase == "Running"` workload logic with a deterministic classifier.

Pod decoding:
- Extend `PodRecord.Metadata` with `ownerReferences: [OwnerReference]?`.
- Extend `PodRecord.Status` with optional `phase`, `reason`, `message`, `conditions: [PodCondition]?`, and `containerStatuses: [ContainerStatus]?`.
- Add private decodable records for `OwnerReference`, `PodCondition`, `ContainerStatus`, `ContainerState`, `ContainerStateWaiting`, and `ContainerStateTerminated`.
- Treat a pod as not ready when `phase == "Pending"`, `phase == "Unknown"`, `Ready` or `ContainersReady` condition is not `True`, or any container status has `ready == false`.
- Treat a pod as restarting when any `restartCount > 0` or a container waiting reason is `CrashLoopBackOff`.
- Treat a pod as failed when `phase == "Failed"` or a terminated state reason exists on a failed pod.

Workload matching:
- Keep namespace targets matched by pod namespace.
- For workload targets, keep existing label/name matching and add selector-backed matching for Deployment, StatefulSet, and DaemonSet metadata when available.
- If adding metadata reads, use only these command shapes, gated by configured target kinds: `["--context", contextName, "get", kind.kubectlResource, "--all-namespaces", "-o", "json"]`.
- Decode only `metadata.namespace`, `metadata.name`, and `spec.selector.matchLabels` for workload metadata.
- For CronJob targets, match active pods by owner reference or existing labels only; do not add schedule history, Job history analysis, or troubleshooting text.

Reason priority per D-06 through D-09:
- Missing matched pods: `state: .bad`, `reason: "no matching pods"`, `affectedPodCount: 0`, `examplePodNames: []`.
- Failed pods: `state: .bad`, reason `"{n} pods failed"` or `"1 pod failed"`.
- Restarting pods: `state: .bad`, reason `"{n} pods restarting"` or `"1 pod restarting"` per D-07.
- Pending or unready pods: `state: .watch`, reason `"{n} pods not ready"` or `"1 pod not ready"` per D-08.
- Warning-only matched workload: `state: .watch`, reason `"latest warning: {reason}"`.
- Healthy matched workload: `state: .ok`, reason `"{running}/{total} pods running"`.

Detail facts per D-10 and D-11:
- `affectedPodCount` must equal the count used in the selected reason.
- `examplePodNames` must contain 1-3 affected pod names sorted alphabetically for deterministic tests.
- `latestWarning` must be the newest `WarningEventRecord` related to the target by namespace plus object name or namespace-only target. Do not attach unrelated namespace warnings to a workload with healthy pods unless no pod-specific warning exists.
- Row reason stays one phrase; pod examples and latest warning are detail fields, not part of `reason`.

Tests to add:
- Missing workload produces `no matching pods`.
- Failed outranks restarting and not-ready when multiple problems exist.
- Restarting reason uses affected pod count: exact expected string `2 pods restarting`.
- Pending and unready merge into exact expected string `3 pods not ready`.
- Warning-only target uses exact expected prefix `latest warning:`.
- `affectedPodCount`, `examplePodNames`, and `latestWarning` are populated and examples are capped at 3.
