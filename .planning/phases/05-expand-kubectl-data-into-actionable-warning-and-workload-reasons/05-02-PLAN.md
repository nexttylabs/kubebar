Update `HealthEvaluator` to build display-only warning summaries and tracked details.

Warning summary rules per D-01 through D-05:
- Keep `MenuCounters.warningEvents` as the compact count.
- Build `warningEventSummaries` from `snapshot.warningEventsSection.value`.
- Cap `warningEventSummaries` at 3 per D-01.
- Render each summary from reason, namespace/object location, and age per D-02.
- Group duplicate events by `reason + objectKind + namespace + objectName` per D-03.
- For each group, use the newest `observedAt`, sum `max(1, count)`, and keep the newest non-empty shortened message.
- Sort groups by newest observed time descending, then reason ascending, then location ascending.
- Cap display to at most 3 summaries.
- Build `location` as `"{namespace}/{objectKind.lowercased()}/{objectName}"` when all fields exist; use `"{namespace}/{objectName}"` when kind is missing; use object name alone when namespace is missing; fallback to `"unknown object"`.
- Build `age` with the existing relative age style (`2m ago`, `1h ago`); use `"recently"` when `observedAt == nil`.
- Shorten messages to 96 characters using a helper in `HealthEvaluator` so detail text only confirms the problem per D-04 and does not expose raw/full kubectl event output per D-05.

Tracked detail rules per D-10 and D-11:
- `makeDisplayItem(_:)` must map `TrackedItemStatus.affectedPodCount`, `examplePodNames.prefix(3)`, and `latestWarning` into `WatchItemDetailDisplay`.
- Detail `stateLabel` must be `item.state.label`.
- Detail `reason` must equal the one short row reason.
- Latest warning display must use the same warning display formatting and short message rules.

Tests:
- Duplicate `BackOff` events for the same pod group into one `WarningEventDisplay` with `occurrenceCount == 4` and newest age.
- Four distinct warning groups produce exactly 3 `warningEventSummaries`.
- A long warning message is shortened before it reaches display.
- A tracked item with 5 example pod names renders exactly 3 names in `detail.examplePodNames`.
- A tracked item with `affectedPodCount == 2` and a latest warning has those fields in `visibleWatchItems.first?.detail`.
