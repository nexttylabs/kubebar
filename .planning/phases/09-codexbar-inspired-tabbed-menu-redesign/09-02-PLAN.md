<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Menu footer -> Settings scene | A menu action opens configuration UI without changing cluster data or saved config by itself. |
| Settings UI -> AppConfigStore | User-edited local configuration is saved through the existing app-owned store. |
| Menu footer -> App termination | Quit leaves UI and requests app termination without crossing into config mutation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Information Disclosure | `SettingsRootView`, `SetupView` | mitigate | Reuse existing setup controls and safe copy; do not show raw command transcripts, token-like strings, kubeconfig paths, stdout, stderr, or JSON. |
| T-09-02 | Tampering | `Settings...` menu action | mitigate | Opening Settings must not trigger `refreshNow`, `kubectl`, or persistence by itself. |
| T-09-03 | Spoofing | First-use/recovery menu state | mitigate | Keep first-use display stale/unconfigured and guide to Settings; do not show missing configuration as healthy cluster status. |
| T-09-04 | Elevation of Scope | Settings surface | mitigate | Settings saves local config only; grep for account, cloud sync, provider, OAuth, Keychain, and multi-cluster additions. |
| T-09-05 | Denial of Service | `Quit Kubebar` | mitigate | Wire Quit only to `NSApplication.shared.terminate(nil)` and source-check that it does not call config mutation paths. |
| T-09-06 | Information Disclosure | Visible verification evidence | transfer | Plan 03 records screenshot paths or redacted pending-human-verification rows. |
</threat_model>
