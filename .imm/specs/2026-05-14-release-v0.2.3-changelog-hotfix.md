# Release v0.2.3 Changelog Hotfix

## Summary

The `v0.2.3` Release workflow built the app but failed while extracting release
notes because `CHANGELOG.md` did not contain a finalized `0.2.3` section.

This slice adds the missing curated release notes so the existing release
workflow can extract a body for the GitHub Release when the tag is replayed.

## Goals

- `CHANGELOG.md` contains exactly one finalized `0.2.3` section.
- The section summarizes the user-visible Pod resource and documentation
  changes included since `v0.2.2`.
- `scripts/extract-release-notes.sh 0.2.3` succeeds locally.

## Non-Goals

- No app behavior changes.
- No release workflow logic changes.
- No automatic local or remote tag movement during implementation.

## Requirements

- R1. Keep the changelog in Keep a Changelog style.
- R2. Keep release notes user-facing and concise.
- R3. Preserve a clean `[Unreleased]` heading for future work.
- R4. Do not make stale or unverified release state look published.

## Verification Expectations

- `./scripts/extract-release-notes.sh 0.2.3` prints the finalized notes.
- `./scripts/swift-quality-gate.sh local` passes or any inability to run it is
  reported clearly.
